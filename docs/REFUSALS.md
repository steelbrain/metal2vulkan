# The refusal surface

Every refusal of something Metal accepts, read from the code: the construction sites of the typed refusals outside tests (`scripts/refusal-surface/refusal_surface.py`, which writes this file; edit its `reach.tsv` and the refusals' own doc comments, never the tables). Sections 8 and 9 are the other half: what a call did wrong, each row a claim that Metal itself refuses an input, with the basis of that claim; section 9 holds the problem enums a `Problem` forwards to, where most of those claims live. Malformed input of no Metal call at all is misuse and is not listed. [`METAL-COVERAGE.md`](METAL-COVERAGE.md) lists the Metal API the runtime has no counterpart for at all.

Columns:

- **What it blocks**: the variant's doc comment, first sentence, and "not scheduled" where the doc says so.
- **Where**: the device condition, from the constructor at its sites: `NotImplemented` and `NotRepresentable` refuse on every device; `needs` names the Vulkan feature, extension, property or limit a device lacks; a driver defect or deviation names the driver. A site that computes its capability says so.
- **Sites**: how many construction sites, then the first two as `file (function)`, with the count where one function builds more than one. "via a helper" counts the places that hand the feature to a function that builds the refusal; "family audit only" is a gap no call refuses, only `supportsFamily:`'s audit (the API is missing: see the coverage map); 0 is a variant nothing builds today.
- **Basis**: where the belief that this input must be refused comes from. Derived from the construction site where the site says it (`device`, `ours`), declared as a last `Basis:` line in the refusal's own doc comment where the claim is about Metal itself, and `-` where neither says it yet:
  - `metal-measured`: Metal itself refuses the input, and a run of ours on a named device or release says so;
  - `metal-documented`: Metal itself refuses it, and Apple's own words say so: a quoted assertion, `NSError` or validation message, a header, or Apple's documentation;
  - `metal-takes`: measured: plain Metal **takes** this input, so the refusal reaches past Metal. An open defect, recorded here rather than left unsaid;
  - `device`: the mechanism is absent: from this Vulkan device, from its driver, or from every Vulkan device;
  - `ours`: this crate's own gap, cap or deadline, or the misuse of a runtime extension Metal has no counterpart for;
  - `unknown`: not established: the refusal stands, and why Metal is believed to refuse this has not been settled;
  - `delegated`: the variant forwards to another problem enum, whose own variants carry the claims. Those enums are read too: each is a family of section 9, named in the row, and a variant of one whose basis is absent or malformed fails the check as a `Problem`'s does. A family whose forwarding variant states a basis of its own instead (a runtime extension Metal has no counterpart for) carries that value in section 9, cited to the variant it comes from.
- **Reach** (hand-kept, `reach.tsv`):
  - `system`: a guest's CoreAnimation, CoreImage or VideoToolbox plausibly reaches it;
  - `app`: a typical Metal app plausibly reaches it from public API;
  - `rare`: public API, but specialized: few apps reach it;
  - `none`: no public API path: malformed or non-Metal input, Apple-private calls, or a cap no valid program of ordinary size meets;
  - `?`: not assessed yet.
  Metal's own refusals (sections 8 and 9) carry no reach mark: every one of them is an argument of a public call.
